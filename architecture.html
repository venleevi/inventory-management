System architecture

Vue 3 SPA

Vite dev server, localhost:3000
Views: Dashboard, Inventory, Orders, Demand, Spending, Reports (Vue Router)
Components: FilterBar, detail modals, profile and language menus

FastAPI service

Uvicorn, localhost:8001
Routes: /api/inventory, /orders, /demand, /backlog, /dashboard/summary, /spending/*, /reports/*
Filtering: apply_filters, filter_by_month (quarters supported)
Validation: Pydantic response models
CORS: all origins allowed
loaded at startup

Data flow

  1. User changes a filter The FilterBar updates shared singleton refs in useFilters (period, warehouse, category, order status).
  2. View reacts and calls the API client Each view builds a filters object and calls a method in api.js, which appends only non-"all" values as query params.
  3. FastAPI receives the request The route handler runs apply_filters and filter_by_month over the in-memory lists.
  4. Response is validated Pydantic models serialize the result as JSON. The dashboard summary aggregates totals (inventory value, low stock, pending orders).
  5. Frontend renders Raw data is stored in refs, derived values are computed properties, and the UI is drawn with custom SVG charts and tables.

Project layout

client/

  • src/main.js: app bootstrap and routes
  • src/App.vue: shell, navigation, global filters
  • src/views/: one file per page
  • src/components/, composables/, locales/, utils/

server/

  • main.py: routes, models, filter helpers
  • mock_data.py: JSON loader
  • generate_data.py: sample data generator
  • data/*.json: the data set

Things worth knowing

  • The API base URL is hardcoded to http://localhost:8001/api in client/src/api.js.
  • Backlog.vue and its API method exist, but no /backlog route is registered in main.js.
  • Inventory filters have no month dimension because inventory data has no time field.
  • Filter state is module-level, so it persists across page navigation within a session.
